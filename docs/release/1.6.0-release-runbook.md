## The one design change: merge, do not rebase

The 1.5 and 1.6 histories split on 2018-01-29 (`7958dc7ac9`). `master` (2023,
`a4bb1bf39`) is an ancestor of neither line, so a rebase cannot apply.

| | Force-move the refs | `-s ours` merge, then fast-forward (chosen) |
|---|---|---|
| Existing clones on `stable` | `git pull` tries to merge 8 years of divergent history. Every 1.5 git install breaks. | `git pull` fast-forwards to 1.6. That is the tested upgrade path. |
| Force push | Needed on three protected branches. | None. Every push is a fast-forward. |
| 1.5 history in `git log stable` | Gone from the branch (tags keep it). | Kept. |

M is one commit. Its tree is R's tree. Its parents are R, `origin/dev-branch`
(which already contains `stable`), and `origin/master`.

## Phase D: the cut (an org owner)

- [ ] Fetch. Check that nothing new is open against `rc-1.6.0`
  (`gh pr list --base rc-1.6.0`). If you cut more RCs, update "21 release
  candidates" in the announcement.
- [ ] Re-read Known issues in the notes:
  `gh issue list --state open --label ready-for-human` and `--label needs-info`.
- [ ] On an `rc-1.6.0` worktree at `origin/rc-1.6.0`, make commit **R**, four files:
  - `packages/web/src/Base/System.php`: fallback `FOG_VERSION` → `'1.6.0'`,
    `FOG_CHANNEL` → `'Stable'`.
  - `bin/bootstrap.sh`: self-URL on line 117 and the usage comment on line 21,
    `working-1.6` → `stable`.
  - `.github/workflows/automerge.yml` (~line 92): allowed base `working-1.6` → `dev-branch`.
  - `.github/dependabot.yml` (~line 26): target branch `working-1.6` → `dev-branch`.

  Commit "Release 1.6.0" with `--no-verify` (the hook drops plugin msgids in a
  plugin-less worktree). Check: `git show --stat HEAD` lists those four files only.
- [ ] Create **M**:

      git merge -s ours --no-ff origin/dev-branch origin/master \
          -m "Release 1.6.0: supersede the 1.5 line"
      git diff --stat HEAD^1 HEAD     # must print nothing: M's tree is R's tree

- [ ] Push, fast-forward only:
  `git push origin HEAD:refs/heads/master HEAD:refs/heads/stable HEAD:refs/heads/dev-branch HEAD:refs/heads/rc-1.6.0`.
  Check: `git ls-remote origin master stable dev-branch rc-1.6.0` shows one SHA.
- [ ] Annotated tag `1.6.0` on **M** (not R): `git tag -a 1.6.0 -m "FOG 1.6.0"`,
  then `git push origin 1.6.0`.
- [ ] `gh release create 1.6.0 --verify-tag --latest --title 1.6.0 --notes-file <announcement text>`.
- [ ] Post the same text to the forum as "FOG 1.6.0 Available".

Checks right after the push:

- [ ] `curl -fsSL https://raw.githubusercontent.com/FOGProject/fogproject/stable/bin/bootstrap.sh | head`
  returns the 1.6 bootstrap.
- [ ] A fresh `stable` checkout reports `1.6.0.0` from `.githooks/lib/fog-version.sh dev-branch`.
- [ ] Lab: install from `master` on a clean VM. The boot menu serves kernel 6.18.59.
- [ ] Lab: `bin/updatefog.sh --channel stable` on a 1.5.10.2534 server completes the upgrade.

The 11 Nov run does not depend on any item here. It installs from
`dev-branch` (`reusable_distro_workflow.yml` default) and skips when
`dev-branch` adds nothing (#47). These items keep CI and docs truthful.

- [ ] fog-workflows: `fogproject-tests.yml`, `branch_install_test.yml`, the distro

  `1.5.10.2534` pin, which is the right 1.5 to test from.

- [ ] Check what the 1.5 web UI reads for "a new version is available". A 1.5
  server that reads `stable` will now offer the one-way upgrade.
